# PCL-Lite-service

PCL Lite 的**更新锚点**。这个仓库里只有一份 `update.json`，没有代码、没有 Release。

## 它解决什么问题

启动器必须写死一个地址才能知道「有没有新版本」。如果这个地址就是发布仓库本身，
那么仓库一改名、一换账号，所有已经装在别人电脑上的旧版本就**永久失联**了——
它们只会对着一个 404 报错，而且没有任何远程手段能把它掰回来。

所以把「地址」和「数据」拆开：

```
客户端（写死，永不改变）
    └──> 本仓库的 update.json          ← 唯一锚点，只有一行指针
             └──> 当前发布仓库/releases/latest   ← 随时可以改
                      └──> Release 自己提供版本号、资产、直链、SHA-256
```

## 内容

```json
{
  "update": "bedkillerspacex-boop/PCL-Lite/releases/latest"
}
```

`owner/repo` 之后的部分（`releases/latest`）只是给人看的，
程序取哪一版由那个仓库 Release 的 `prerelease` 标记决定。

**发新版不需要动这个文件。** 只有「发布仓库搬家」时才改那一行。

## 三条规矩

1. **仓库必须公开。** 私有仓库对匿名用户就是 404，和「不存在」无法区分，客户端只能报 404。
2. **仓库名和地址永不改变。** 改地址等于把所有旧版本一起掐断。真要换地方，
   要在新地址放一份内容相同的 json 并让旧地址重定向过去，而不是直接改客户端里的常量。
3. **不要归档、不要改默认分支名。** 客户端读的是 `main` 分支的 raw 地址。

## 背景

原来的锚点放在 `Pcl-Lite` 组织下。2026-10 那个组织被 GitHub 标记隐藏，
组织下所有仓库对匿名访问全部 404，清单的六条通道和 Releases 兜底源一起断，
客户端没有任何退路。这就是为什么锚点要放在一个稳定的个人账号下。

客户端侧的说明见主仓库的 `docs/UPDATE.md`。
